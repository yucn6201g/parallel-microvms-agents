# mvm で MicroVM のエージェントに作業を任せる (司令塔)

この PC は司令塔です。コードを書いてテストする作業は、MicroVM の中のエージェント (Claude Code / Codex) が行います。
この PC では `npm` / `pnpm` / `yarn` / `pytest` / `playwright` / `docker` / ビルドなどの重い処理を動かしません。RAM を節約するのがこの仕組みの目的です。

mvm の呼び方 (このまま使う):

```bash
{{MVM}} <command> ...
```

## 守ること

- **費用がかかる操作は、ユーザーの了承を得てから**: `up` / `fleet` (VM を起動する)、`stop` (終了する) は、何台・何をするかを伝えて確認してから実行する。`stop-all`、`infra`、`image`、`secret` は、ユーザーが明示的に頼んだときだけ
- **台数はクォータの範囲内**: `{{MVM}} doctor` の「同時に N 台まで」を超えない
- **認証情報を指示文に書かない**: トークンやキーは `mvm secret` で登録済みのものを使う (ユーザーに貼らせない)
- **待つときに sleep を繰り返さない**: `{{MVM}} wait` を使う

## 手順

### 1. 状況を確かめる

```bash
{{MVM}} ls --json          # 動いているセッション (名前、状態、リポジトリ、ブランチ)
{{MVM}} doctor             # 何台まで同時に起動できるか
```

### 2. タスクを分けて、指示を書く

- 1 台に 1 タスク。各 VM は `pmva/<name>` ブランチで作業するので、変更はぶつからない
- 指示には **終わりの状態** まで書く: 「テストが通るまで直し、commit して push し、PR を作って。最後に変更点と PR の URL を報告して」
- MicroVM のエージェントは、この PC のファイルや会話を知らない。必要な知識 (仕様、方針、関係するファイル、制約) は指示に書く
- 起動時の指示は 4KB まで。長い仕様はリポジトリにファイルとして置いて「docs/spec.md を読んで実装して」と書くか、起動後に `send` で送る

### 3. 起動する (ユーザーの了承を得てから)

```bash
{{MVM}} up <name> --repo <リポジトリの URL> --prompt "<指示>"
{{MVM}} fleet <台数> --prefix <接頭辞> --repo <URL> --prompts-file <ファイル>   # 1 行に 1 つの指示
```

名前は英小文字・数字・ハイフン (例: `fix-login`)。

### 4. 終わるまで待つ

```bash
{{MVM}} wait <name>... --timeout 540 --json
```

- 終了コード 0: 全台が終わった (または人の対応が必要)。2: 時間切れ → 同じコマンドをもう一度実行する
- `--any` を付けると、どれか 1 台が終わった時点で返る (終わったものから順に見る)
- 返ってきた `state` ごとの対応:

| state | 意味 | 次にすること |
|---|---|---|
| `done` | 応答が終わった | 5 へ |
| `waiting` | 許可・入力を待っている (`message` に内容) | `{{MVM}} peek <name> 40` で画面を見て、`{{MVM}} send <name> "<答え>"` で答える (許可の選択肢は番号を送る)。判断できなければユーザーに聞く |
| `error` | 認証の失敗や利用上限など、API のエラーで止まった (`error` に種類、`message` に文章) | `authentication_failed` / `billing_error` はユーザーに知らせる (認証情報やプランの問題なので、送り直しても直らない)。`invalid_request` は `message` を読み、認証情報の問題ならユーザーに知らせ、それ以外なら `peek` で確かめる。`rate_limit` / `server_error` は時間をおいて `{{MVM}} send <name> "続けてください"` で再開する。同時に動かす台数が多ければ減らす |
| `ready` | 最初の指示がない | `send` で指示を送る |
| `stalled` | 画面も CPU も長く動いていない | `peek` で画面を確かめる |
| `exited` / `failed` | エージェントが終了した / 起動の準備に失敗した | `peek` で確かめ、ユーザーに知らせる |
| `suspended` | VM が一時停止している (ふつうは作業が終わった後。作業の途中で止まったこともある) | `{{MVM}} peek <name>` で再開して画面と状態を確かめる。作業中なら `wait` に戻り、終わっていれば 5 へ |
| `terminated` | VM が終了している (8 時間の寿命、サスペンドのまま 6 時間、毎晩の自動停止、`stop` のいずれか) | `{{MVM}} ls --all` で確かめ、ユーザーに知らせる。続きが要るなら、了承を得てから `{{MVM}} up <name>` (保存したワークスペースを戻して続きから始める) |
| `unreachable` | AWS から VM の状態を取れない (認証切れ、権限、通信) か、VM の状態 API が応答しない。`wait` は終わったとみなさず待ち続け、時間切れのときや `--json` の `sessions` に出る | `--json` の `error` と、時間切れのときに出る `!!` の行 (理由とやること) を読む。認証切れ (`aws sso login` が要る) は、この PC のユーザーにしかできないので知らせる。権限・通信は `{{MVM}} doctor` で確かめる。直ったら同じ `wait` をやり直す。VM の状態 API の応答がないだけなら `{{MVM}} peek <name>` で確かめる |

`{{MVM}} ls` / `watch` / `top` に `UNKNOWN` と出たときも `unreachable` と同じです。VM が終了したわけではないので、`stop` や `up` で作り直さず、表示された理由 (認証切れ → `aws sso login`、`AWS_PROFILE` の確認、`{{MVM}} doctor`) に従ってユーザーに知らせます。

### 5. 結果を確かめる

```bash
{{MVM}} result <name>        # エージェントの最後の応答 (報告)
```

- 変更の中身は GitHub で確かめる (`gh pr view` / `gh pr diff`、または `git fetch origin pmva/<name>` して `git diff`)
- 直してほしい点があれば `{{MVM}} send <name> "<追加の指示>"` → 4 に戻る
- **VM が書いた自動メモリを確かめる** (`up` の `--memory` や `MEMORY_SYNC=true` で共有しているとき。VM のエージェントが誤ったこと・一時的なことを覚えると、次の VM や手元の会話に伝わってしまう):

```bash
{{MVM}} memory log --since <起動した時刻 (2026-11-24T10:00:00Z など) か 2h> --json   # VM が書いたメモリの一覧 (origin が VM の名前)
```

  - `origin` が VM の名前で `action` が `write` のものが、その VM が書いたメモリ。`name` ごとに、メモリのフォルダ (`{{MVM}} memory status` に出る) か、`pull` 後の手元のファイルを読む
  - 誤り (事実と違う、リポジトリに無い)、一時的なこと (今日のブランチ名、作業中の状態)、認証情報らしいものがあれば、**何をどう直すかをユーザーに伝えて了承を得てから**、`{{MVM}} memory revert <名前>` (1 つ前の版に戻す。`--to <時刻>` で版を指定) か `{{MVM}} memory rm <名前>` (全部のマシンから消す) を実行する。先に `--dry-run` で内容を確かめる
  - `rm` は S3 のファイルを消すので、この PC (操作用の認証情報) で実行する。VM の中では実行しない
  - 問題がなければ何もしない

### 6. 終える (ユーザーの了承を得てから)

```bash
{{MVM}} stop <name>          # ワークスペースを保存してから終了 (後で --restore latest で再開できる)
```

## 様子を見るとき (必要なときだけ)

この PC のコンテキストを節約するため、画面や記録の全文は読まない。

```bash
{{MVM}} peek <name> 40                     # 画面の最後の 40 行
{{MVM}} follow <name> --once --lines 20    # 直前の 20 件の過程 (指示・思考・実行・結果・応答)
{{MVM}} top --json                         # VM のメモリ。メモリ不足 (oomKills) ならユーザーに知らせる
```

ユーザーに進み具合を見せたいときは、`{{MVM}} follow`(流れ続ける表示) や `{{MVM}} view <name>` (画面を読み取り専用で表示) を、ユーザー自身のターミナルで実行するよう案内する。

## ユーザーへの報告

セッションごとに、状態、エージェントの報告の要点、PR の URL、残っている課題を短くまとめる。
